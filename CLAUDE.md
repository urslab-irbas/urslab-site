# URSlab website — notes for Claude Code

Bilingual static site (Astro) for the Unmanned Robotic Systems Laboratory, Institute of Robotics, BAS.
Target domain: https://urs.ir.bas.bg

## Structure
- Bulgarian is the default language at `/`, English at `/en/`. Every page exists in both; the menu switch links to the same slug in the other language (`src/lib/i18n.ts`).
- Content lives in `src/data/` — edit data, not markup:
  - `team/<id>.ts` — one file per staff member (BG/EN names and titles, ORCID, links, interests); order in `team/index.ts`
  - `publications.ts` — CURRENT list (submitted / in press) shown on „Публикации“; items with status 'published' move automatically to the yearly archive page by year (archivePages.ts). Filters on „Публикации“ search all site publications (`allPubs.ts`: currentList + archiveList)
  - `archive2022.ts`, `archive2025.ts`, `archive2026.ts`, `archiveEarlier.ts` — yearly publication pages (/publications/2022-2024/, /2025/, /2026/, /earlier/); each entry goes on the page of its publication year; shared types, categories and topic tags are in archive2022.ts; the list of pages (order in „Архив“) is `archivePages.ts`. 2025/2026 come from the BAS report „XX а: Всички публикации – публикувани“ (share = % authors from IR)
  - `allPubs.ts` — all publications on the site (archive pages + publications.ts, de-duplicated by DOI/title) → per-member „Обобщен отчет“ at /team/<id>/report/ (button on each Team card)
  - `contrib.json` — (authoritative copy lives in branch `data`; main has `[]`) publications entered via the site form /publications/new/ (GitHub issue → `.github/workflows/publication.yml` + `scripts/add-publication.mjs` validate with `src/lib/pubSchema.js`, append here, open a PR); distributed to yearly pages by `archivePages.ts` (a page for a new year is created automatically). Team members with `github` in their profile get the „+ Нова публикация“ button. Form rules: `status` (published / in-press / submitted) — unpublished ⇒ `cat: 'sub'`, no metrics; no DOI ⇒ `idType` (issn/eissn/isbn/eisbn) + checksum-valid number (stored as `issn`/`isbn` + `idType`). The Action verifies identifiers in public registers (`scripts/verify-ids.mjs`: doi.org + Crossref/DataCite title match; ISSN → NACID NRS API `nrs.nacid.bg/api/Public/Nrs/GetInactiveAndActive?intNumber=` → ISSN Portal; ISBN → NRS → Crossref → Open Library), refuses if not found/unreachable, sets `nrsId` from NRS, then publishes WITHOUT manual approval: commits `src/data/contrib.json` + `publish-log.md` to the unprotected orphan branch `data` (a personal-account repo cannot put GitHub Actions in the main ruleset bypass list), dispatches `deploy.yml`; deploy/build/publication workflows overlay `src/data/contrib.json` from `data` onto `main` (the copy in `main` is `[]`). Logs to `publish-log.md` (branch `data`); on success the bot writes NO comment (comments e-mail everyone in the issue) — the result block with „Върни“ is appended to the issue body (edits send no mail); comments only when action is needed (refusal, error) — rule (23.10.2026): the System e-mails only requested information or what needs action, to whoever must act; ticking „Върни“ in the issue body (or in the old bot comment) (owner only) runs `revert-publication.yml`. Scimago/Google Books are not used (bot-blocked / quota). The form locks after „Запиши“ and polls the public GitHub issues API for the request's labels (публикувана/отказана); it pre-checks for an already-published issue with the same title. Rejections @mention the author with per-error fix steps (HOW map in add-publication.mjs). Branch `data` has its own `.github/workflows/redeploy.yml` (push → dispatch deploy.yml) because push workflows run from the pushed branch's tree.
  - Research-area cards (`AreaCard.astro`): „Автономна навигация“ keeps its own page and the count from `publications.ts`; all other areas count ALL site publications (`allPubs`, incl. form entries) and link to /publications/area/<key>/ — counts update automatically on every build.
  - `nspsdRefs.ts` + `nspsd.ts` — publications under the National Scientific Program “Security and Defence” (grant D01-74/19.05.2022) → page /projects/nspsd/ (button „Публикации“ on the project card; view `Archive.astro` with `program="nspsd"`). `nspsdRefs` lists title fragments (+ task numbers); entries already on the site are taken from `allPubs` (site spelling is authoritative), others are full records in `nspsdExtra`. Every listed publication gets `fund` = „NSP DS, MES grant D01-74/19.05.2022“; the same text is shown as „Финансиране“ in the „Публикации“ list. The build fails if a reference matches nothing.
  - `/docs/NNPSO_Publications_IR-BAS.xlsx` — the NSP DS publications in the programme's Excel template, GENERATED on every build by `src/pages/docs/NNPSO_Publications_IR-BAS.xlsx.ts` (exceljs) from `nspsdPubs` — so it always matches /projects/nspsd/. Template: `scripts/nspsd/template.xlsx`; extra per-row data (type, full venue name, volume/pages, link, ISSN/ISBN, language, note) in `src/data/nspsdExcel.ts` (keyed like nspsdRefs; optional — new entries are filled from the site record); publisher data by DOI (full author names, date, volume/issue/pages, abstract) in `src/data/nspsdMeta.json` (Crossref snapshot). Button „Експорт към ННП „СО“ (Excel)“ on /projects/nspsd/, next to a link to https://nsp.secade.bg/bg/rezultati/publikacii.
  - `nspsdActivities.ts` — NSP DS „Докторанти по ННП СиО“ (/projects/nspsd/phd/) and „Конференции и семинари“ (/projects/nspsd/events/: 1. participations, 2. organised events), view `src/views/NspActivity.astro`; buttons next to „Публикации“ on the project card (`projects[].more` in content.ts). Papers are title fragments resolved against the site's publications (build fails if not found).
  - `irShare.ts` — % IR authors per publication (IR authors ÷ all authors, as in the BAS report): the BAS-report value (`share`) wins; otherwise computed at build (`shareCalc`, shown with * and a tooltip) for every published item (not cat 'sub'); 0 % if no IR author. Publications with no lab member and no reason to be in the lab report are removed (e.g. the ECG paper from publ1.pdf). Co-author RULE (07.10.2026): every co-author outside the team must have a known institution — registry `COAUTHORS` in `src/lib/pubSchema.js` („Фамилия, И.“ → institution; „ИР-БАН“ ⇒ counted as IR); the institution is taken FIRST from the publication itself, only then from other sources (BAS report, OpenAlex); when unclear, ask the lab head. The form shows known co-authors and asks for the institution of unknown ones (field `affil`, validated in `validate()` as `affil-needed`, also by the GitHub Action); the build fails (`withShare`) on any record with an unknown co-author — add them to COAUTHORS when entering data by hand. The summary tile „Процент автори ИР“ / „Percentage of IR authors“ = average share of the shown items with a share (fractional counting in %), tooltip explains it.
  - `series.ts` — expected indexing (latest SCImago SJR + quartile, SJR_YEAR) of the series/journals where submitted / in-press papers will appear; matched on `venue`, shown as „Очаквано: Q4 · SJR 0.165 (2025)“ / „Expected: …“ on items with cat 'sub' (Archive.astro) and unpublished items (PubList.astro). Papers stay in „Подадени / под печат“; update the numbers when SCImago publishes a new year.
  - `books.ts` — separate pages for monographs/books (/publications/books/<slug>/, view `Book.astro`): large banner (lightbox + PDF with live links in `public/docs/books/`, indexable — exception in `.htaccess`), full bibliographic data, abstract, contents, JSON-LD `Book`, `citation_*` meta tags for Google Scholar, og:image. The archive record's title links to it via `page` (no extra badges or buttons in the lists). Books: `gyros` (monograph, 2000), `GPS2000` (co-authored monograph NAVSTAR/GLONASS, 2000), `GPS2013` (textbook, НВУ, 2013); optional fields `coauthors`, `kindNote` (shown next to the kind label when there is no `hab`; textbooks get a green label), `registries` (e.g. booksinprint.bg), `udkSource`, `ebook`; COBISS/UDK are optional. Banner sources (HTML + title-page images from the books) are outside the repo; banners: `public/docs/books/<slug>-banner.jpg|-1200.jpg|.pdf`.
  - `citations/` — verified citations, ONE DIRECTORY PER TEAM MEMBER (`citations/<id>/index.ts`; citations belong to the person, because self-citation depends on the author). Format `citations/types.ts` (cited work `no` = NACID list number, `pub` = isbn/doi/title fragment matched against the site's publications — build fails if no match; `cites` = text in NACID style, year, indicator `ind` '12'/'13'/'14'); points per indicator in `citations/rules.ts` (Area 5: D-12 = 10, D-13 = 3, D-14 = 2). Shown only on „Обобщен отчет“ (Archive.astro with `member`): button „Цитирания X“ under the year of every published item (dialog with the NACID-style table) and „Цитирания X“ left of „Изтегли CSV“ = sum for the filtered items (dialog with all their citations). Each member directory also has `contrib.json` (citations entered through the form; main has `[]`, the real copy is in branch `data`, overlaid by build/deploy/publication workflows with `git checkout FETCH_HEAD -- src/data/citations`). Form entry: „+ Цитиране“ in the per-publication dialog (only members with `github`) → /publications/new/?m=<id>&cite=<pubKey> (citation mode of NewPub.astro) → issue „[Цитиране] …“ → `.github/workflows/citation.yml` (builds first, then `scripts/add-citation.mjs` reads `dist/publications/citables.json`) → `validateCitation` in `src/lib/pubSchema.js` (publication rules + NACID: no self-citation, year ≥ cited, D-12 needs Scopus/WoS, D-14 needs journal ISSN, no duplicate citing source; evidence source `src` = doi / url / pdf) + `scripts/evidence.mjs` (doi → Crossref metadata fills empty fields + reference list must contain the cited work if deposited; url → page/PDF text; pdf → file attached to the issue, read with pdftotext installed in citation.yml; match = cited DOI/ISBN or ≥70 % of title words (or its `tr`) within 40 words of the member's surname; for url/pdf the citing title must be in the text) + `verify-ids.mjs` → `citations/<id>/contrib.json` in branch `data`; revert via `revert-citation.yml`. Points per indicator: `CIT_POINTS` in pubSchema.js (used by rules.ts). New team member → add a directory with `index.ts` and `contrib.json` (`[]`) and register both in `citations/index.ts`. A confirmed citation of a shared work is written to the `contrib.json` of EVERY team co-author of the cited work (not self-cited, not already entered; `confirmedBy` = the confirming member); authorization = GitHub account of any team co-author of the work or the owner. Automatic search: `.github/workflows/citation-scan.yml` + `scripts/scan-citations.mjs` (monthly cron, manual issue „[Търсене на цитирания] …“ from the report button by a member with `github`, max once per 24 h — the owner is exempt, or workflow_dispatch; one-time e-mail recipient: line „Имейл: <addr>“ in the owner's issue or input `mail_to`) — OpenAlex / OpenCitations COCI / Semantic Scholar; skips known citations and self-citations; every candidate with a DOI is PRE-VERIFIED like a confirmation (Crossref metadata + reference list, validateCitation; auto-filled fields in a wrong format, e.g. an article number as pages, are dropped, never a reason to refuse — same rule in add-citation.mjs and `fromCrossref`/`PAGES_RE`); result issue(s) „[Нови цитирания] <date>“ (split into parts above ~58 000 chars; previous open result issues are closed) with task-list checkboxes per citation `<!--c:<id>:<opt>-->` (opt 12s / 12w / 13 / 14 / x) → `.github/workflows/citation-confirm.yml` + `scripts/confirm-citations.mjs`: ONE tick by a team co-author of the cited work with `github` (or the owner) opens a bot issue „[Цитиране] …“ (`<!-- by:<login> -->` = who ticked, `<!-- scan:<issue>:<id> -->`) and dispatches citation.yml; „Откажи“ → `state.rejected` (never proposed again); the checkbox lines are replaced by a status line `<!--s:<id>-->` which citation.yml updates with the result. citation.yml processes ALL open „[Цитиране]“ issues in one run (`scripts/run-citations.mjs` → add-citation.mjs each; one build/commit/deploy). Indexing (Б1, issue #121): `scripts/index-lists.mjs` reads lists uploaded by the owner to branch `data`, `citation-scan/index/` (`scopus*.xlsx|csv` = Scopus Source List with ISSN/EISSN/coverage years; `wos*` = Web of Science MJL, no years; other names = other databases, informational only) and `classify()` proposes ONE indicator with a reason (Scopus in the citing year or WoS → 12s/12w; else journal with ISSN → 14, proceedings/book → 13); it is listed first and marked „← предложено“, other boxes stay; without a Scopus list nothing is proposed (behaviour as before Б1). Measurement: `scripts/index-eval.mjs` / `.github/workflows/index-eval.yml` (manual; Summary + comment in #121). ## Rules
- Always update BOTH languages when adding or changing text.
- Academic titles: BG "доц. д-р инж.", "доц. д.н. инж.", "гл. ас. д-р инж."; EN "Assoc. Prof. Dr. Eng.", "Assoc. Prof. DSc Eng.", "Chief Assist. Prof. Dr. Eng.".
- Do not publish full texts of papers under review; title, authors, venue, abstract only.
- Run `npm run build` after changes and fix any errors before committing.

## Commands
- `npm install` · `npm run dev` (http://localhost:4321) · `npm run build` (output in `dist/`)

## Workflow
- Changes reach `main` only via Pull Request approved by the lab head. CODEOWNERS maps each profile file to its owner.
- Every PR runs `.github/workflows/build.yml` (npm ci + build); the built `dist/` is attached as an artifact `urslab-dist`.
- Colleague instructions (Bulgarian): `CONTRIBUTING.md`.
- `.github/workflows/deploy.yml` uploads `dist/` to the server (lftp mirror, no deletions) on every push to `main`, using `DEPLOY_*` repository secrets. Merge = live.
- Search engines: `@astrojs/sitemap` → `sitemap-index.xml` (filter in `astro.config.mjs` excludes 404 and the publication form), `public/robots.txt`; `Layout.astro` emits canonical + hreflang (bg/en/x-default) and JSON-LD `ResearchOrganization` (home, team); pass `noindex` to Layout for pages that must not be indexed. `public/googleef6ca6200dc25ccb.html` is the Google Search Console verification file — never delete it.
- Visitor statistics: GoatCounter script (`is:inline`) in `src/layouts/Layout.astro`, dashboard https://urslab.goatcounter.com.
- Research areas ↔ publications: each area in `content.ts` has `tags`; area cards (`AreaCard.astro`) link to `/publications/?area=<key>`, which pre-selects that area's filter. Areas with no matching publications show "forthcoming".
